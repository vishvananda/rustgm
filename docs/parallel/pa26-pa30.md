# Worker B: PA26, then PA30

Model: `gpt-6.1-sol`; reasoning effort: `high`.
Worktree: `rustgm-pa26-work`; branch: `pa26-work`.
Follow `../parallel-work.md` and repository instructions.

PA26 owns typed language/library hooks: operator/index dispatch, iteration,
question-mark control flow, built-in derives, formatting and option_env's nominal
Option identity. Extend existing traits and method selection using explicit
registered identities. Keep metadata demand-loaded and preserve the no_std
boundary; do not fabricate core/std source paths or recognize arbitrary user
items merely by spelling.

Start with operator/Index source-to-native checkpoints, then expand the other
families. Reuse selected method-call facts and ordinary lowering rather than a
second dispatch engine. Coordinate builtin vocabulary with Worker C's intrinsics
and closure call-trait interfaces with the integrator. Test evaluation order,
receiver loans, early return, derive bounds and formatting independently.

After integration, PA30 owns C ABI, repr attributes, linkage and imported/exported
declarations. Pure ABI classification and C fixtures can progress before final
crate metadata integration. Agree a callable ABI identity with the integrator
and symbol/import identities with Worker A's PA29 before changing shared types.
Use pinned CPPGM capabilities with explicit interoperability tests; backend
extensions are separately scoped work, not silent prerequisites. Include
aggregate arguments/results, callbacks and exported globals in both directions.

The [library bootstrap plan](../library-bootstrap-roadmap.md) prioritizes actual
upstream declarations after the current coherent iterator checkpoint. The compiler
owns lang-item identity, desugaring, builtin derives/formatting, intrinsic rules
and required internal features. Ordinary Option/Result/Iterator implementations
and containers come from core/alloc sources. Canonical declaration/body factories
are temporary; do not expand them into a parallel standard library.

Inventory the pinned core source, then establish one complete source-declared
binding path with duplicate/forged-identity rejection and actual consumer use.
Coordinate shared registry and generic-body transport with the integrator and
Worker A. Preserve PA26's full operator/iteration/derive/formatting contract and
PA30 interoperability obligations; source bootstrap changes implementation order,
not the release requirements.
