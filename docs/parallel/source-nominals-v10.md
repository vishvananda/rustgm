# PA29 source nominal transport checkpoint

This work adds the explicit tag-10/version-10 `module-nominals-v10` source
profile. Versions 0–9 and tag-11 Provided retain their previous encodings and
permission boundaries. This checkpoint does not close PA29 or original core/Pin
transport.

The source provider exports actual named struct declarations through the existing
collector, canonical declaration ledger and completed header contracts. A nominal
recipe names the artifact/declaration address and actual generic arguments. Fields
retain their real source site, owner, ordinal, name, type and module visibility;
there is no fabricated resolver field declaration. Struct shape and Members
installation share their existing validation kernels and prepared destination
batches. Each batch reserves before publication and binds exact destination
identity/frontier; an exclusive ready borrow precedes consuming publication.

Imported constructor and field operations remain typed original-body operations.
Structural validation substitutes the actual nominal arguments before comparing
each field type, validates complete field count and actual owner, and checks
source-module access. Reconstruction selects genuine destination Fields from
Members. Ordinary formation, original-input, original-body, ownership and instance
proof paths remain required. No synthetic nominal AST or shared producer Store
stands in for loading the serialized provider.

The frozen packet is `pa29/tests/source-nominal-outcomes.json`, with original
fixture fingerprints. The independent Rust 1.98.0 run compiles the provider and
fresh positive consumer separately, links a C observer and returns 7. Independent
opponents reject: moved Packet, private Hidden field, wrong generic argument,
escaping local borrow, and a same-layout wrong nominal owner. Independent v3

receipts are local evidence, not committed build products.

## Boundaries

Enum, union, unit/tuple shapes, richer representation, field annotations, custom Drop,
source Pin/fundamental roles, broader early-lifetime/default/const-generic schemas
regular consumer re-export of foreign generic nominal types, and a complete
original core artifact remain explicit gaps. The new profile must
not be described as complete nominal transport or an executable Pin contract.
Unsafe/const ordinary callable policy follows the existing version-nine protocol.
The source role fences remain in force.
