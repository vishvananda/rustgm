# Caller-region premises in body trait queries

Lane B batch of 2026-11-08, branch `implement/caller-region-20261108` on
origin/main `078d3f238`. It repairs the two recorded gaps of
[scoped-proof shim globs](scoped-proofs-shim-globs.md), section 1:

```rust
pub fn item<'x, F: Out<O = Option<&'x u8>>>(s: &mut Wrap<F>) -> Option<&'x u8> {
    s.next() // impl<B, F> Iterator for Wrap<F> where F: Out<O = Option<B>>
}
```

rustc 1.98.0 accepts it. This compiler rejected it, and the `FnMut` form
`caller-region`, with "trait obligation requires an unambiguous matching
assumption or implementation".

## 1. Reduction

Thirty-one exploration probes (`obj/lane-b3/t3/{probes,probes2,probes3}`,
generated by `gen.py` from the fixtures' pinned prefix, sha256 `437463f6…`)
separate the cases. rustc 1.98.0 accepts all of them.

- Rejected by this compiler: the fixture shape, an unused or discarded result,
  a nominal `R<'x>` output, an output without `Option`, path and qualified
  calls, a signature naming the projection, `&'x T`, `'x: 'y`, an annotated
  result, a by-value receiver (so no callable binder is involved), a generic
  helper, a bound-only use with no result at all, `impl<B: ?Sized, …>` (so the
  impl parameter's `Sized` requirement is not involved), and `'x` also present
  in the goal's own input.
- Accepted by this compiler: `'static` and type-parameter outputs, `u8`, a
  premise-only body normalization (`get(f)` with `F::O`), an impl parameter
  fixed through the self type, a signature-only use, a region from an impl's
  own projection value over the goal input, and a region only in a quantified
  premise's trait input.

The bound-only probe refutes the hypothesis that a region inference variable
stays unresolved. Regions are fixed identities here, with recorded
equalities, and that probe has no result to infer.

## 2. Cause

Analysis-only builds (`obj/lane-b3/t3/dev/dbg2`–`dbg4`, instrumentation not
committed) give one path for every rejected probe:

1. `prepare_bound_environment` (`bodies/bounds.rs`) adds, beside each premise
   that names a caller universal, a copy with that universal replaced by its
   body alias: "Body calls express caller universals as free aliases …
   Original subjects remain available for declaration-context annotations."
   The method environment holds `<F as Out>::O == Option<&'x u8>` twice: with
   the declaration-form `RegionId(0x8000_0001)` and with the alias
   `RegionId(2)`.
2. Body trait queries took that environment as it is
   (`trait_query_environment` returned `method_environment` unless an
   inherited projection environment existed).
3. The selected impl's condition `F: Out<O = Option<B>>` normalizes
   `<F as Out>::O` through `equalities::select`. Both copies match the
   projection's inputs and their results differ, so the selection is
   `Ambiguous`.
4. `resolve_premise_result` returns no resolution, the normalization stops
   `Deferred`, the trial's wakeups wait, and the search yields as a top-level
   `Progress::Inferred`. Nothing changes afterwards, so the body fails at
   `trait_goals/inference.rs:77`.

`caller-region` takes the same path with the quantified `FnOnce::Output`
premise (`QuantifiedId(6)` with `0x8000_0001`, `QuantifiedId(10)` with the
alias). The passing probes have no alias copy (`'static`, type parameters) or
run through `projection_environment`, which substitutes the universal
aliases (`body_binders != 0`) so the two copies coincide. Trait assumptions
already converge: `trait_assumptions` maps each escaping clause through
`alias_clause`.

## 3. Audit of declaration-form goals

The repair gives every body trait query the alias view, so a goal that named a
caller universal in its declaration form would no longer meet a premise of the
same form. Each origin of a body trait query was probed
(`obj/lane-b3/t3/audit`, 14 drafts). An analysis-only build
(`obj/lane-b3/t3/dev/forms2`) printed the escaping binders of every goal that
reaches `select_pending_goal`, and of every canonical requirement before its
`alias_predicate`:

| Origin | Probe | Goal form | Before | After |
| --- | --- | --- | --- | --- |
| let annotation naming `'x` | a00 | alias | rejected | accepted |
| annotation well-formedness needing the equality | a01 | no body query | accepted | accepted |
| annotation well-formedness, `'x` in the trait input | a02 | canonical, alias before aliasing | accepted | accepted |
| turbofish naming `'x`, equality bound | a03 | alias | accepted | accepted |

| annotated `&'x mut` receiver | a10 | alias | rejected | accepted |

Every goal had zero escaping binders: no declaration-form universal reaches a
body trait query. Call instantiation and turbofish lifetimes are aliased
(`alias_region`, `alias_type` in `bodies/calls.rs`), qualified paths through
`bodies/generics.rs`, closure signatures through `closures/contextual.rs`, and
canonical requirements through `alias_predicate` before their query. Where a
declaration-form annotation term meets an alias-form result (a00), the body's
own region equality relates them: `prepare_universals` records
`(alias, bound)` for every body binder. a08 is a separate cause (a selection in
a closure body before any body step has aliased a caller lifetime, first
recorded as the closure's declared return type); it fails the same way before
and after and is recorded under section 8.

The ambiguity drafts a11–a13 (two written premises whose results differ in a
type) are rejected by rustc (E0284) and by this compiler with "associated type
requires an unambiguous validated implementation", before and after.

## 4. Repair

`trait_query_environment` (`bodies/trait_goals.rs`) always returns
`projection_environment(node)`, the cached alias view that body projection
queries already use. `Pending::has_inherited_environment`
(`bodies/projections.rs`) loses its only caller and is removed. The method
environment, and so the declaration-form premises for declaration-context
annotations, is unchanged. No `sema::traits` file changes for this repair.

Cost: the view is the existing per-body `OnceCell`
(`projections.data.environment`), so the repair adds at most one cached
substitution fold per body with lifetime binders, charged as before through
`account_work(fold.steps)`. Bodies without binders, or whose environment has
only parameters, reuse the same `Arc`.

## 6. Predicate split

Task 2's two spellings of "this frame's inputs are normalized" are different
states, so they stay two predicates:

- `own_inputs_normalized(frame)`: this frame's own `advance_inputs`
  normalization is ready. `complete_builtin` calls it to choose
  `prove_normalized`.
- `normalized_inputs(frame)`: the inputs arrived normalized (`Frame::child`,
  or a borrowed query in normalized or projection mode) or the frame
  normalized them itself. It was already that disjunction at `6cd9f9e82`; it
  is now spelled through `own_inputs_normalized`.

The split changes no behaviour.

## 8. Findings and open items

- Audit a08 (`|w: &mut Wrap<F>| -> Option<&'x u8> { w.next() }`) is rejected
  with "missing lifetime argument"; rustc 1.98.0 accepts it. It is a separate
  cause, unchanged by this repair, and not a declared control. This entry first
  blamed the closure's declared return type. A later reduction showed that the
  annotation does not matter: a selection in a closure body through a premise
  naming a caller lifetime fails when it runs before any body step has aliased
  a caller lifetime. [Closure entry aliases](closure-entry-aliases.md) repairs
  it.
- Arrived-normalized frames and plain `prove()`: not reached. Two
  analysis-only builds (`obj/lane-b3/t3/dev/arrived1`, `arrived2`, binaries
  `94164e54…` and `d1e59941…`, patches kept, binaries retired) instrumented
  `complete_builtin`. They printed every frame whose inputs arrived
  normalized (`Frame::child`, or a start in normalized or projection mode),
  whichever branch it takes, and every plain `prove()` call as a positive
  control. The corpus was 336 fixtures from 20 projection, sizing and lifetime
  spec directories of `pa31`, and three of `pa29`, plus seven drafts
  (`obj/lane-b3/t3/arrived-drafts`). The drafts put builtin `Copy`, `Clone` and
  `Sized` declaration requirements on projections that normalize to
  `(&'x u8,)`, `fn(&'x u8)`, `&'x u8` and a nested projection. Plain `prove()`
  ran 2,125 times in 157 files, every time for `Sized`, 24 times with a caller
  region. No call had arrived inputs, and no frame with arrived inputs
  reached `complete_builtin`. So there is no probe to report. A `Frame::child`
  goal is the trait requirement of the opened associated application
  (`opaque::overrides::requirement`). Builtin bounds have no associated
  items, so that source is not expected to reach this branch. The start paths
  (`select_normalized`, normal-form `begin_borrowed`) can carry a builtin
  goal, but none did in this corpus.
- Cleanup note: `storage.py prune` treats vendored upstream `.a`/`.o` files
  inside obj input snapshots as generated output. Retiring six `inputs` pins
  removed wit-bindgen 0.57.1's `src/rt` objects; the crates.io registry copies
  reproduce all six recorded manifests
  (`obj/cleanup/lane-b-retired-pins-20261108.json`). The integrator records it
  as an open storage-tooling item.
