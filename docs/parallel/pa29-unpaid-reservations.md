# Unpaid Provided reservations

This checkpoint adds private owned reservation inputs;
it does not activate Provided publication, import, canonical recipes or execution.

The private semantic session consumes the existing resolver Report and semantic
Declarations/Store. It does not parse or clone either owner. The resolver appends
real source-free definitions and lexical scopes through the existing artifact
root, declaration, owner and body-scope producers. A private catalog owns the
complete selected artifact's declaration/body coordinates. No lexical binding,
external alias, role, semantic header or Graph is installed into the report.
New semantic None cells reserve storage only; they establish no paid proof.

The session owns indices and handles instead of borrowed self-references. It
retains the actual arena identity and the immutable inventory allocation. Failure
returns no session and drops its report/store; caller-owned attempted work and
peak bounds survive. This checkpoint interns no types. Its dormant private entry
has one narrowly reasoned dead-code expectation pending the later canonical
RecipeCursor consumer. There is no escaping TypeId, Graph or install API.

The ordinary Functions path reuses the same factored reservation producers and
retains its pending-binding preflight and installation order. The catalog's
existing storage estimator now supplies one before-allocation callback; ordinary
installation uses a no-op callback. Unpaid reservation charges that same estimate
before catalog hash/row allocations, including rejected attempts. The optional
cold resolver Work gains one peak-bound counter; hot Body/Contract fields stay
unchanged. Bounds conservatively include existing moved vector/interner growth.

Five focused private controls cover genuine full-family reservation without
names/roles/import publication, real foreign inventory/catalog and changed cells,
failed work/storage budgets, actual moved arena identity and empty semantic slots,
and replaced arenas/invented semantic payment. The unchanged three-body/nine-role
fixture is retained byte-for-byte. Existing Functions codec/fresh-client and
numbering-admission controls remain required alongside these tests.
