# Closed named records across crates

The maintainer can export and import closed nongeneric named records through
schema-one profile three. This checkpoint implements the family described in
`pa29-closed-nominal-plan.md`; PA29 remains planned. Generic body exports,
generic and lifetime-parameterized nominals, other nominal shapes, methods and
trait contracts, aggregate constants and allocation graphs remain required.

Export planning consumes completed typed function signatures and member facts.
Standalone public records are roots even when no function names them. A single
discovery walk retains reachable private layout declarations and checks their
semantic contracts. Canonical external identities determine record ordinals;
one immutable artifact graph serves every function and field root. The original
signature-local encoding remains the path for profiles zero through two.

Imports reserve all nominal identities before remapping the shared graph once.
Named fields retain external owner, declaration order, exact type and access.
They have no fabricated source node, constructor body or const-call permission.
Completed aggregate fields enter the ordinary nominal sizedness preparation;
rules are sealed with local declarations, including in import-only consumers.
A local record containing an imported record therefore uses the same completed
size contract as other aggregate fields.

The current family supports default Rust representation and scalar, nested
record and static shared-reference fields. Private reachable fields can carry
hidden record layouts without exposing their names or enabling construction.
Public signatures and public fields that require an unexported private type
are explicit profile boundaries. Copy/Clone derives, Drop or other trait
implementations, inherent methods, generics, representation attributes,
non-exhaustive contracts and mutable-reference fields are also explicit
boundaries. Their retained Rust-positive fixtures must eventually be supported
with their real contracts; they are not classified as invalid Rust.

The local `non_exhaustive` consumer validates word form and the actual struct,
enum or enum-variant owner, retaining source-bound facts for export checks.
Its defining-crate construction and matching behavior is ordinary Rust. The
record exporter consumes those facts and keeps the same explicit profile
rejection; it does not publish an artifact lacking the foreign contract.

The source inventory declares two providers, nine accepted clients and six
language rejections, plus ten Rust-positive profile boundaries. The two
providers use the same crate and item spellings with different crate identities.
Clients cover construction, calls, returns, nesting, patterns, private values,
static reference fields, local wrappers, nominal mismatch and moved values.
All 27 source outcomes are independently qualified with Rust 1.98.0. The nine
accepted clients execute against both rustc and the pinned CPPGM object backend.
Reordered dependencies and repeated exports preserve exact results.

Focused qualification in `obj/parallel/pa29-export-v6/` passes 19 metadata codec
tests, 25 crate-linking tests and all four native crate-linking groups, including
the earlier scalar, constant and borrowed-signature groups. Strict release
all-target/all-feature Clippy passes; the file/architecture audit reports 1,604
files and zero findings. Failed earlier batches remain retained. The size-rule
regression is checked both through source-free imports and a real separately
compiled local-wrapper client.

At widths 8, 32 and 128, import counters separately vary function count and
record count. For R records and F functions, they retain R records, R fields,
R+1 remapped type nodes, F signatures and 2F function roots. These counters
verify shared graph remapping; they do not establish whole-compiler timing or
allocation bounds. Combined release/text checks and affected performance
measurements are recorded in
[the publication checkpoint](pa26-pa30-records-checkpoint.md). The private tail check in
`obj/parallel/pa29-export-tail-v1/` preserves exact profile zero/one/two metadata
and LowIR against the published baseline and passes the 90 harness checks,
grouped discovery, layout and upstream validation. No text oracles are generated by this
private checkpoint.
