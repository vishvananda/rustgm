# Generic callable context

Generic argument closure expressions now receive their contextual input and result
signature from the already instantiated, canonical Fn output requirement. The body
indexes those requirements once by the actual argument term; entering a closure
performs a direct lookup and builds only the selected signature. No lookup rescans
the body or its declaration predicates. Ordinary bodies leave the index unallocated.
The original trait and output requirements still need their complete selection and
lifetime proofs. This context grants no callable permission.

Quantified clauses retain their binder, including unused slots. Unquantified
requirements shift enclosing captures beneath the signature's empty binder.
Unresolved type and const inputs use the existing isolated closure interface;
nested function pointer binders remain local. This repairs the case in which an
unconstrained closure input acquired a query-local universal during later trait
selection and then correctly failed the universal export barrier. That barrier is
unchanged.

`pa24/tests/generic-context-outcomes.json` declares 21 source outcomes before text
oracle publication: 15 accepts and six rejects. Pinned rustc independently compiles
objects for the positives and rejects the negatives. The positive programs also
execute through rustc and CPPGM, checking results for called closures. Controls

separate and unused lifetimes, nested closures, nested function pointer inputs and
unresolved generic input types. Crossed outputs, local/static/captured escapes,
insufficient call permission and an uncontextual input-only result remain rejected
by their actual lifetime or selection rule.
