# PA30 nested aggregate callable checkpoint

The fixed x86-64 C profile accepts nonempty aligned `repr(C)` structs containing supported scalar fields, nested structs with that same representation, and fixed array fields. One retained ABI plan still supplies the argument/result span, alignment and INTEGER/SSE/none/MEMORY classes for imports, exports and callbacks. Top-level arrays, Rust-layout/packed/union/enum aggregates, empty structs, unsupported scalar shapes and other target ABIs remain boundaries. Variadics are a separate integrator-owned slice.

Composite demand allocates a private cache beneath `abi::classification::Plans`. An iterative traversal validates every field representation, natural alignment and checked span before returning a class, including objects larger than sixteen bytes which use MEMORY. Arrays validate one canonical element graph and their checked stride/product; large MEMORY arrays do not expand every element. Eightbyte summaries are cached by `(canonical TypeId, byte offset modulo eight)`, with integer dominance applied after placing actual scalar leaves. This matters for `Inner { u32, f32 }`: its standalone INTEGER summary cannot be shifted as a coarse block when it starts at outer offset four. The shifted nested/array controls require INTEGER/SSE. Work and retained storage share the existing classifier budgets.

The ordinary flat scalar-field path allocates no composite cache. `Passing`, `Object`, `Plan` and all public sparse LowIR records keep their representations. Measured sizes are `Passing=16`, `Object=16`, `Plan=40` bytes. Only `Plans` gains an eight-byte optional cache pointer (112 to 120 bytes on this build). Cache hits retain no extra data. Checked layouts and completed nominal definitions remain the authority; diagnostic source text and field spelling do not participate in classification.
