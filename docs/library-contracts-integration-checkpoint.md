# Source library contracts and alias binder integration

The integrated candidate combines canonical alias binders, actual collected
source-header admission and shared imported-input kernels, source-defined Not,
source layout/Clone bodies, local specialization dispatch and the bounded
2021/2024 driver option. No assignment or original core/alloc/std artifact is
completed by this checkpoint.

## Implementation

Alias expansion composes surrounding scopes through the existing charged
typed-input machinery, retaining unused slots and callable-local binders without
copying ancestor paths. Alias lifetime relations, original/normalized projection
consumers, objects, complete declaration validation and imported transport remain
required. The alias execution/export fence stays closed.

Actual source-header admission binds collected columns to the same source and
inventory allocation in a fresh consumer. Imported trait inputs use one ordinary
and private translation kernel. Method conformance uses the same defining-origin
validator as header readiness: Declaration environments coincide, while genuine
Contract body environments remain distinct. This supplies no full checked-header,
role/member, original-body, fresh-instance or public Provided permission.

Source Not authenticates the actual trait, Output and method before ordinary
implementation/caller/body proof; primitive emission is erased only afterwards.
Closed source layout queries reuse ordinary field instantiation and ABI layout.
Pending structural definitions cannot become permanent negative source-layout
answers. The actual source provider retains the SizedTypeProperties associated
constants, generic wrappers, nominal Clone and provided clone_from bodies.
No bootstrap algorithm or backend behavior was added.

Local specialization dispatch retains the real defining method and complete
arguments. Both projected-result consumers keep parent lifetime obligations;
scalar inheritance does not invent a stronger caller lifetime. Default impl,
associated-value specialization and imported graph/defaultness transport remain
closed. The driver edition option preserves existing cfg and runtime inputs;
source-core artifact publication remains restricted to its existing 2024 profile.
