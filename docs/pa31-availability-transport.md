## Ownership and checks

The cold versioned columns cover every emitted declaration and module binding.
Policies retain regular/const kind, feature, level and actual declaration/site
or binding/site origin. Root policy, trait-implementation requirements, kind,
const applicability, ancestry, grouped import leaf sites and complete coverage
are validated before publication. Private/parameter absence remains valid.
Source collection reuses the completed local inventory and actual reserved
declaration/site numbering. A parent use-item annotation joins its resolved
import index and real leaf site; it never guesses a declaration or source site.

Imports retain the immutable catalog/inventory identity and one paid canonical
remap. Known imported declarations lacking policy coverage remain Required;
they cannot become local absence. A copied or missing owner, including a missing
whole import carrier, rejects against the admitted source-client inventory.
Foreign use checks run with no local Library or feature requests. Request-only
clients do not acquire staged local API exposure requirements.

Ordinary calls check the actual target and module prefixes. Reexport annotations
remain truthful independent policy/feature records, but do not add an ordinary
call requirement or erase the target's requirement. This distinction follows
the retained pinned-Rust counterexamples. Regular availability provides no body,
const execution, role, borrow, layout or provided-default permission.

Ancestry intervals are built once. Source-owner candidates are ordered once and
queried by a charged binary predecessor/containment check, with an explicit
overlapping-incarnation fence. No Body, Code, NodeFacts or Reference fields grow.
