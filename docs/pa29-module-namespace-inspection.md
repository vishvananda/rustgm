# Private source-module namespace prerequisite

This checkpoint is under development. It adds no source descriptor/profile, wire tag,
Interface, public SourceClient namespace mode, body execution or CTFE permission.
The original core artifact remains unavailable. PA29 owns the declaration/namespace
and catalog contract; PA31 owns the original-source and source-provider fixtures.

Current readable Functions/v1 source profiles only admit the root namespace. Their
producer requires role-only traits and rejects every active restricted trait before
publication. The old byte contracts and those guards are retained. Legacy PublicNames
uses ExternalDef and cannot represent an actual source Trait target. Traits must not
receive fabricated function/linker identities.

The private producer borrows each genuine prepared ordinary trait through its actual
source declaration, Self owner/schema, flags, parameters, members and complete bounds.
The language-role binding pass remains separate and installs only actual registered
roles. The kernel can later be reused by another private producer; it grants no
Provided-profile publication or default-body permission.

A namespace snapshot follows the existing full source original/body proof pipeline.
It moves the existing columns and BodyCatalog owner rows once into an immutable cold
owner. Public module-scope exports carry their actual module DeclarationRef and target
DeclarationAddress. Private defining modules remain in the declaration forest even
when public aliases bypass their canonical path. HeaderIndex and the ordinary body
validator check the snapshot structurally; there is no Descriptor accessor.

Canonicalization precomputes keys once and uses fallible charged comparison sorting.
Its bound is O(B log B + compared-key bytes), plus linear row/module traversal and
actual string/capacity storage. No alias path unfolding, per-use tree walk or extra
owner graph is introduced. The source rows remain shared with the private remap.

PendingNamespace consumes a real resolved report, reserves actual declaration/scopes,
preflights binding keys and installs/freezes one existing Catalog. It exposes no
mutable report, public imported inventory or SourceClient policy. Module identities
remain authenticated foreign declaration/catalog coordinates; Scope.module=ModuleId(0)
is bookkeeping and cannot prove local ancestry, privacy or implementation permission.
Warm queries validate their exact immutable snapshot, catalog handle and current cells;
failed owner/budget attempts are charged. Failed transactions expose no completed owner.

`pa31/tests/spec/private-module-namespace` contains the actual source fixtures.
Two focused groups cover real non-role headers/module aliases/homonyms/growth and
catalog coordinates/foreign owners/warm mutations/transaction failure/public guards.
The ordinary namespace dependency of original num::nonzero is preserved across its
public num alias without admitting unsafe or associated-result transport.

The first independent runner retained all raw observations but misnamed its producer
metadata result.rmeta. All 24 client observations were invalidated as extern-loading
failures, including two accidental matches of `private` in source filenames. A frozen
narrow continuation retained 16 genuine provider observations, reconstructed only 7
needed metadata files with a legal lib prefix, and executed the 24 clients. All 40
metadata/object predictions now match; reconstructed bytes were actually compared and
all 7 match their retained hashes. No native/runtime or RustGM implementation claim
comes from those independent observations, and the earlier 74 restrictions controls
were not repeated.

Future restricted-trait transport needs complete per-trait policy columns, actual
canonical defining-module provenance, foreign-source impl denial and validation of
legitimate provider-owned impls. Merely widening ordinary_functions() would erase the
current Unrestricted-only invariant and is prohibited. Original ZeroablePrimitive also
still needs its actual unsafe/associated-result/stability contracts. Broader schema,
consumer and publication work requires a separate review and qualification.
