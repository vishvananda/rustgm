# Fundamental owner policy checkpoint

This checkpoint removes the requirement that a fundamental annotation belong to
a sizing language item. Pinned Rust1.98 permits actual structs and traits, with
the fundamental feature or genuine macro allowance on the attribute name.
It does not require rustc_attrs. Malformed/unsafe-wrapped, duplicate and wrong
owner claims still fail. A lookalike name grants no language role or intrinsic.

The existing configured-owner walk retains a cold fundamental promise under its
actual header, authentic source image, effect range and defining identity. The
existing source contract ledger pays retained storage and cumulative failed
queries. No ordinary AST/body/type/declaration field or parallel owner registry
is added. Semantic consumers borrow the completed policy; explicit public/source
queries authenticate the actual source incarnation. General ordinary annotation
claims do not impose a source-provider requirement on ordinary crates.

Nominal locality and trait knowability remain separate rules. The orphan walk
looks through references and all type arguments of foreign fundamental wrappers
in their real order. An earlier uncovered parameter remains an error even when
a later argument is local. A local nominal remains local without inspecting its
arguments. Dyn ownership follows the principal trait; a marked principal does
not make a foreign object transparent. The foreign-wrapper traversal uses a
paid visited set so shared type subtrees do not expand exponentially; ordinary
roots allocate no traversal storage. The existing overlap consumer admits closed
fundamental trait absence alongside its existing local-trait rule, retaining
open/projected/downstream uncertainty and genuine selection evidence.

Existing metadata already encodes fundamental policy for exact sizing-role
traits. That validated path remains supported. General nominal/trait policy is
explicitly fenced until authenticated transport is implemented. Consequently,
the foreign general-policy branches are implementation preparation rather than
a claim of completed cross-crate qualification. Original FieldRepresentingType,
Pin and Fn declaration/body graphs, complete compatible-world rules, metadata
transport and every whole assignment/library release gate remain required.
