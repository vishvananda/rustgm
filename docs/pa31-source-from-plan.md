## Typed implementation order

1. Add the source language role and separate diagnostic identities using the
   existing reservation/catalog tables. Authenticate declaration kind, actual
   current source owner, arity, origin, feature authority and completed headers.
   Diagnostic identity alone supplies no fallback authority. Ordinary trait
   conformance still checks actual method signatures and bodies.
2. Register the semantic preference only for an actual still-pending typed
   From<floating-root> obligation whose Self is resolved f32. Reuse body-goal
   notifications and nested solver-condition wakeups; handle a Self or argument
   that becomes resolved after the initial observation. Completed, cancelled,
   changed-owner and failed-payment cases cannot retain a preference.
3. Consume that preference at the existing numeric dependency frontier. Inspect
   only real waiters of a changed numeric root, so shared obligations select the
   same type regardless of queue order. Preserve projection barriers, explicit
   types, rigid inputs and ordinary/default-only paths. No per-call whole-goal
   scan, new global census, AST reparse or duplicate numeric cache is justified.
4. Preserve ordinary record widths and allocation-free absent paths. A proposed
   same-width Fallback payload for the preferred argument must be measured;
   source-role validation belongs to the existing cold completed ledger.
   Temporary growth and attempted work must be paid before mutation. Check
   widths8/32/128, shared roots, late aliases, cancellation and failed payments
   alongside an ordinary f64 control.
5. Qualify the complete source corpus through the real frontend, deterministic
   LowIR and locked backend. Original const From/reflexive/reservation contexts
   still require their real bodies, const/unsafe/API permissions and conformance.
   An authored finite trait cannot stand in for that original graph.
6. Transport authenticated From ownership through a declared supported metadata
   capability before claiming exported core or downstream compatibility. Existing
   wire0–v8 profiles must not silently acquire a role or policy they do not carry.
   An explicit development fence is unfinished PA29 work, not a completed crate.
