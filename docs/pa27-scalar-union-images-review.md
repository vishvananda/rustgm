# Scalar union byte images

This checkpoint executes constants for unions whose concrete fields are all primitive scalars. Immutable images contain the union's exact target-layout byte span and an independent initialized-byte bit mask. Fields overlap at offset zero; there is no active member. Stores preserve untouched bytes and initialization bits and publish a new image. Copies retain the original immutable ID. Selected reads require initialized bytes and validate bool/char representations; merely storing bytes does not validate every alternative field.

The private `Value::Image` arena is lazy. Public `View::Image { size }` and `Reader::image` expose borrowed typed bytes/mask without arena IDs. Mask bit i corresponds to byte i, least significant first within each u64 word. The constants view prints exact initialized byte hex, `??` for unknown bytes and sixteen hex digits per mask word, in word-index order. `Reader::field_types` continues rejecting union structural field interpretation. The native serializer may choose zero for unknown padding; it never changes the CTFE mask. Zero-data placement checks the same image type and layout size as ordinary serialization.

The arena limits each image to 64 KiB and all retained images, families, masks, buffer temporaries, headers and index capacity to a conservatively charged 64 MiB. Work is checked before family copies, image cloning and scalar decoding. Copies share IDs; stores allocate immutable replacements. Private invariants establish budget rejection before allocation/publication, immutable copy snapshots, malformed field-identity rejection and cached family/layout reuse. No host addresses or input-language unsafe execution occur in the compiler.

The unchanged original demanded and unused invalid-bool and uninitialized-byte fixtures now reject for their actual validity failures. The historical valid-bool fixture now succeeds without changing its bytes. Thirty-five independently qualified full Rust objects and all three frontend views match the separately declared outcomes; four native groups compare independent Rust execution with the pinned CPPGM backend. Controls include integer widths/sign bits, float bits and negative zero, char validity, partial stores, snapshots, nested storage, statics, shared and mutable references, a closed generic family and an AtomicU32 metadata context. The ordinary no-image input has byte-identical types and LowIR output to baseline 7385a2dc.

Capabilities remain distinct from invalid Rust. Pointer/reference/function/aggregate field families and union-field addresses remain explicit unsupported boundaries. The accepted large-alignment input demonstrates the image-size limit. The retained named-const field-address hypothesis is independently rejected by Rust with E0745; the frontend currently rejects at its address boundary, which does not establish E0745 enforcement. The unchanged uninitialized union field store rejects in executable ownership checking; earlier type inspection remains status zero.

The original PA28 zero-array-repeat-return fixture is unchanged and now supported through PA25's integrated inline execution. Its earlier explicit unsupported expectation is superseded in the draft receipt; independent native execution calls the original factory. This integration result does not expand the Image profile.

Qualification passes six focused source/native test binaries (33 tests), four private invariants, strict all-target/all-feature Clippy, the file audit (1,323 files, zero findings), assignment layout and pinned upstream verification. The first Clippy pass identified dispatcher length and the first audit identified fixture include policy; both were corrected and the affected tests/lint/audit rerun.
