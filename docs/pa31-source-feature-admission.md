## Request and use contracts

The private resolver policy distinguishes a recognized request that enables a
specific existing construct from a request that grants no capability. It adds
`never_type` and `stmt_expr_attributes` to the existing four source feature
bits, resulting in six. `asm_experimental_arch` is recognized without adding a bit.
This is consistent with the pinned compiler's stable x86-64 assembly target
classification, but implements neither assembly syntax nor lowering. The exact
source builtin claim facade still rejects unsupported asm/global_asm claims
before any fallback stub can expand. Same-named ordinary macros stay ordinary.

The typed use validator requires the actual root feature for a never type
outside a direct function result, or for an expression-position attribute.
Parent positions distinguish direct function/function-pointer/closure results
from nested types and callable-bound output positions. Stable item/statement
and method-receiver positions do not acquire expression-use obligations merely
from their spelling. Requests under nested owners cannot mutate the root set.
Only enabled retained root attributes supply requests; disabled cfg/cfg_attr
owners remain undemanded. Existing source declaration, intrinsic, sizing,
signature, original-body and caller proof obligations are unchanged.

## Publication and traversal

`resolve::load::load_with_context` validates its completed configured package
before returning it. `resolve::expansion::analyze_with_context` validates after
the expansion worklist finishes and before returning its report; the loader
constructor used inside expansion does not run the loading completion check.
Ordinary name finishing does not repeat validation. These are different
published trees, with one traversal per applicable phase rather than one pass
per include, expansion or readiness retry.

Ordinary programs return on absent `Package.source_core` before allocating
traversal storage or inspecting syntax. Source mode walks each actual Unit root
once, carries only temporary parent positions, and ignores disabled subtrees.
Inline modules are part of their containing tree and are not revisited as
separate module roots. Include templates remain provenance: their installed
copies are checked under actual parents, with original/generated spans and
ordinary expansion diagnostic projection preserved. Macro token bodies and
retired intermediate syntax are not additional active trees.

No AST, Package, Resolution, SourceCore or other persistent record fields were
added. The feature set remains one byte. Layout assertions for the inherited
Package272/SourceCore72 and the temporary Position are prepared, not measured
on this source. Work counters charge actual units, skipped template headers, active nodes, edges and
retained attributes, including progress before a rejected use. They are local
to validation; no persistent cache or registry was introduced.

## Declared controls awaiting execution

The new grouped frontend root `feature_requests` reuses the unchanged v1
independent outcomes for recognized/unknown requests, root cfg_attr, never
aliases, stable direct never results, missing expression gates, disabled uses,
forged nested requests and unsupported asm claims. It adds declared hypotheses
for installed type includes, generated types, out-of-line diagnostic ownership,
function-pointer results, nested result types, statement/tail/array-bound and
grouped expression attributes. Those additional hypotheses must be qualified
with the pinned Rust toolchain before acceptance claims or implementation
adjustments.

Private tests prepare width/depth/expansion and include/module-unit axes at
8/32/128, comparing actual visits with unique reachable configured identities.
The controls separate total source size from the number of templates/units,
test the ordinary zero-work path, count rejected uses and reject a forged
configured attribute owner. No counter results or passing lint/audit claim is
made yet. The next allowed guarded batch must format, compile and qualify these
focused controls, including uncertain expression-position edges, before this
checkpoint can be integrated.

Actual prelude_import, source Copy/callable/Tuple declarations, internal macro
permissions, generalized sizing proof transport and public SIZE/ALIGN wrapper
execution remain dependencies. Direct compile-time-only layout kernels do not
gain a synthetic runtime implementation here. Incomplete PA26/PA30 requirements
remain required work on the path through upstream core, alloc and std.
