# Bare atomic selection and source permissions

The fixed target's bare atomic fact selects real source items, including items
generated by a macro or configured through a captured metadata fragment. The
selected helper must resolve and type-check normally. No feature request is
needed for bare `target_has_atomic`.

A selected nested `target_has_atomic_load_store` predicate still requires the
actual `cfg_target_has_atomic` request or its authenticated macro allowance.
The direct and generated missing-feature cases remain required rejections.
Target truth and a lint cap provide no permission. The authorized case retains
the genuine source feature request.

Independent pinned Rust stable/bootstrap comparisons establish all six
outcomes before reference generation. Stable mode removes the bare-selected
items, exposing missing helper names or hiding the nested gate demand; the
bootstrap-capable course target must preserve the bootstrap outcomes. Existing
captured-string, gate-order and macro-allowance controls remain required.
