# Checked unsafe-call source bodies

Profile eight retains the actual unsafe obligation discharged at each checked call. The full preserved provider and forwarder remain byte-identical to the profile-seven Rust-positive requirement. Added scalar and const bodies are authored observers, not original library replacements. Fresh clients must retain ordinary API, signature, unsafe, const and body proofs. Profiles zero through seven keep their exact bytes and denials.

The closure, nested-item and macro inputs independently establish Rust lexical rules using the pinned ordinary Rust library; they do not substitute for the separate genuine NoCore provider/client transport. Any unsupported closure transport or internal-macro authority remains a valid-positive requirement. Safe calls use Safe even inside unsafe blocks. UnsafeFunction describes the actual caller declaration, never callee-derived permission.

The first frozen oracle predicted that `allow_internal_unsafe` alone granted an unsafe call; pinned Rust rejected it with E0133. The retained primary checker and lint pass show that this attribute affects the unsafe-code lint, while a real unsafe block is still required. The successor retains that counterexample and separately compares marked/unmarked external-macro blocks. No new lint producer is part of this transport work.

The new source envelope keeps the exact v7 callable capabilities and adds one call-request byte: Safe=0, ExplicitUnsafeBlock=1, UnsafeFunction=2. Older envelopes consume no such byte and reject non-Safe in-memory requests. The source producer records only successfully checked unsafe obligations in sparse body-owned rows, authenticates their solved signature, and pays growth and copying before publication. Fresh reconstruction checks the actual imported caller and Call operand; this retained context is not an executable instance, API grant, const permission or paid proof. Always-comptime remains fenced.

The source recipe cache retains caller context for the existing transitive callable summary: named items and their containers contain context-owned application handles. Scalars and other noncallable recipes still share their existing keys. Extra named-item/reference rows are bounded by those already context-owned applications; unsupported tuple, array and associated-projection transport remains explicit. Historical first-encoding controls and the qualified v7 provider bytes remain checked.
