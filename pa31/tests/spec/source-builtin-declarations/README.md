# Known source builtin declarations

The closed role catalog comes from Rust88d9's actual compiler registry, not a
prefix or a metadata exemption. Bang, attribute and derive invocation kinds are
separate from source declaration syntax. The original 24 role ordinals and
ordinary synthetic slot allocation remain fixed. Added roles initially had no
execution consumer; no placeholder body may run. The current availability table
now admits the independently qualified pointer-pattern consumer for pattern_type.
Its actual source feature, ownership and input checks still apply.

`roles.tsv` binds the 61 exact names, kinds and existing execution availability;
`all-known-roles.rs` retains a genuine declaration for each. Other inputs oppose
unknown claims, wrong owners/forms, aliases, invocation kinds, disabled uses and
the SourceCore derive metadata bypass. `contract.json` distinguishes primary
registry facts, frozen candidate expectations and unrun independent observations.
The original contract retains its declaration-only predictions; the availability
column is maintained as real consumers qualify, without changing the Rust source
inputs or pinned role identities. The MacroRules derive-form restriction is an explicit supported-profile denial;
it is not presented as an independently observed Rust semantic rejection.

This does not implement assertion expansion, tracing, attribute rewriting,
derive output, allocator glue, contracts, EII, assembly, proc-macro hosting or
foreign macro transport. Each execution family remains required at its owning
assignment. Ordinary supported derives keep their current real consumer.
