# Known source builtin declarations

The closed role catalog comes from Rust88d9's actual compiler registry, not a
prefix or a metadata exemption. Bang, attribute and derive invocation kinds are
separate from source declaration syntax. The original 24 role ordinals and
ordinary synthetic slot allocation remain fixed. Added roles initially had no
execution consumer; no placeholder body may run. The current availability table
now admits the independently qualified pointer-pattern consumer for pattern_type.
Its actual source feature, ownership and input checks still apply.

`roles.tsv` binds the 61 exact names, kinds and existing execution availability;
`all-known-roles.rs` retains a genuine declaration for each. Other inputs oppose
unknown claims, wrong owners/forms, aliases, invocation kinds, disabled uses and
the SourceCore derive metadata bypass. `contract.json` distinguishes primary
registry facts, frozen candidate expectations and unrun independent observations.
The original contract retains its declaration-only predictions; the availability
column is maintained as real consumers qualify, without changing the Rust source
inputs or pinned role identities. The historical `wrong-derive-form.rs` filename
and source bytes are retained, but the expected result is now acceptance:
pinned rustc 1.98.0 accepts this library metadata input in editions2021/2024.
The registry supplies the derive invocation kind independently of its
`macro_rules!` source form. This declaration does not enable From execution;
the private consumer control rejects that use before expansion work.

The declaration producer grants no execution permission. Assertion expansion
and the registered derive families now have separate source-owned consumers;
tracing, attribute rewriting, allocator glue, contracts, EII, assembly,
procedural-macro hosting and foreign macro transport remain separate work.
Ordinary supported derives keep their current real consumer.

`unavailable-bang.rs` preserves the historical Assert alias and original
candidate rejection prediction. Assert now reaches its actual missing-condition
diagnostic. The new `unavailable-asm-alias.rs` preserves genuinely unavailable
Bang coverage: pinned Rust accepts the complete source in editions 2021/2024,
while the candidate rejects before invoking assembly or publishing expansion
work. Its source and outcomes were declared before the four observations.

Nonempty `attributes(...)` lists now have a separately authored typed declaration
producer and exact checked-header API. It retains canonical identifiers/spans on
the existing cold header, preserving role/provider/source identity and checked
empty versus missing state. It grants no derive execution or global helper scope.
See [the helper declaration checkpoint](../../../../docs/source-builtin-helper-declarations.md)
for independent hypotheses, actual lint outcomes and qualification status.
