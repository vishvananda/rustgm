PA31 owns the actual attributed source declaration and call identity; PA28 owns
constant pointer provenance and wrapping execution; PA27 retains independent
unsafe-call and pointer-access obligations. This cluster does not use an ordinary
bootstrap `core::ptr` factory or substitute an inbounds `add` operation.

`88d9e12ae178fab0fb5cc050a94da85685d449ea`'s
`library/core/src/intrinsics/mod.rs` at bytes 37329..38155 (docs, actual attributes
and the complete const unsafe signature). Its SHA-256 is
`fb23f889415dd729caaef4f891ee8dc99ee50f4d67ebebbca13accd0fb192515`.
The original Rust attribution and licenses remain in the repository's upstream
source records. `contract.json` records the exact source-derived foundation and
all authored protocol inputs. The foundation is the already qualified source
role/Location/pointer protocol, with explicit observer Clone/Copy implementations;
it supplies no ordinary library method implementation.

The frozen Rust 1.98 / edition-2024 / Linux x86-64 protocol covers signed positive
and negative offsets, leaving an allocation and returning before reading, maximal
and minimal signed wrapping words, zero-sized displacement, numeric raw/null
words and real constant evaluation. The C observer compares unsigned address
words without dereferencing any out-of-bounds or noncanonical result. A distinct
unmarked ordinary `arith_offset` executes its authored identity body and has a
different trace. `generic-forward.rs` retains a genuine `at<T>` original and its
closed runtime call. Invalid signatures/generic headers, a missing unsafe block,
a nonconst ordinary source target and a reached invalid dereference are separate
negative inputs. No spelling grants an intrinsic, const or memory permission.

The independent v1 attempt rejected the intended positive because the real
inherited `location_fixture` const policy had no feature request. That failed

matches seven metadata outcomes and two native traces. The separately frozen v3

`obj/parallel/wrapping-offset-v1/oracle-v{1,2,3}/`. The current contract includes an
explicit provenance erratum: the old range used Unicode text indices and omitted
the final newline; the retained fragment and all Rust/C input bytes never changed.
The corrected byte slice was checked directly against the pinned source.

Candidate checks consume the actual source catalog/header, full instance,
checked direct call and reached body/Code. Runtime uses the existing signed
machine-word multiply and typed byte-index kernel without a memory access.
Constant execution preserves either the original allocation root and write
restriction or a numeric address without invented provenance; wrapping changes
coordinates only. Bounds, initialization, liveness, alignment, validity and write
permission remain obligations of the later access. Effective zero displacement
preserves the pointer exactly, after evaluating both call arguments.

Required boundaries remain whole original-library/runtime acceptance and source
intrinsic metadata transport, which is explicitly fenced in declaration and
body publication. CTFE representations other than supported thin symbolic and
numeric words, including literal-text/function/wide pointer values, require their
own producers; this checkpoint grants no such capability. Existing inbounds add
checks and raw dereference checks remain independently qualified controls.
