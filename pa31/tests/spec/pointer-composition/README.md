# Raw pointer composition controls

PA28 owns the intrinsic/validity contract; PA31 owns the genuine source binding.
`predictions.json` inventories each input and freezes outcomes before observation.
The oracle calls actual pinned core helpers. Candidate source controls must keep
those helper and UB-check bodies, rather than supply compiler library factories.
Preserve NOTICE and the Rust88d9 source pin. No invalid-access native execution is
permitted; only the valid runtime companion executes. Dynamic metadata and wire
transport remain explicit pending boundaries.

`index-foundation.rs` and `slice-indices.rs` are authored actual const
Index/IndexMut declarations and generic implementation bodies used by the
maintainer's original pointer/assembly fixture contexts. They retain real
indexing and ordinary selected trait, output, borrow and const checks. The
pointer context already supplies the actual Pointee/Metadata foundation for the
second file. The unstaged array-only assembly context instead uses
`runtime-index-foundation.rs`: the actual const trait protocol, ordinary
non-const generic array implementations and real indexing bodies, without
library stability attributes. Its ordinary runtime original reaches LowIR;
using those implementations in a constant rejects. The runtime-order pointer
fixture has no indexing and keeps its original provider without these helpers.
`index-predictions.json` binds those inputs and the independent companion.

Pinned Rust1.98 no_core attempts retain an upstream `fully_perform` ICE101;
that is unqualified infrastructure evidence, not a semantic rejection or parity
success. `standard-companion.rs` keeps the authored helper bodies under standard
core, removing only duplicate language/diagnostic ownership attributes. Its

metadata/object/native checks with `9 91` plus LF. This narrower companion does
not close the full no_core source, const, borrow or metadata requirements.
