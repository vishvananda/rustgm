# Constant source callback selection contracts

These are pre-implementation contracts. No new independent Rust or RustGM result
is claimed. The JSON declares expected outcomes and source/client hashes before
probes. The unchanged original CTFE-positive fixture and existing semantic
opposites remain in the runtime cluster and are referenced without replacement.

Each new source retains the original qualified semantic provider prefix and its
body-bearing `const_eval_select` placeholder. Correct CTFE enters the evaluated
F callback directly; ordinary runtime enters G. Conditional callback fixtures
retain B's eligibility frontier, and nonempty conditional payment shapes remain
unsupported by the current payment profile.

The provider declarations derive from Rust core revision
`88d9e12ae178fab0fb5cc050a94da85685d449ea`, MIT OR Apache-2.0, Rust project
contributors. The conditional fixtures deliberately use a distinct const Clone
implementation so the independent contract can satisfy its actual const bound.
No original source is altered or stripped of attributes.

The [interface proposal](../../../../docs/pa31-const-select-ctfe-proposal.md)
names the actual reached-call, tuple, source-body and payment consumers and the
remaining scope. Neither these fixtures nor that proposal activates PA31.
