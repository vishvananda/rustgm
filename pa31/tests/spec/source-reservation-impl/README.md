Reservation declarations do not implement a trait for ordinary callers. These
source cases preserve independently observed pinned Rust outcomes, including
ordinary/const real implementations, compatible-world coherence, malformed
attributes and actual unsafe/member/body restrictions. `contract.json` records
the original failed prediction for an associated type and its corrected,
unchanged-input observation. An independent real implementation permits that
same reserved associated definition; no blanket type-member prohibition follows.

The direct exported reservation method is a required native positive: its real
body may emit without granting a selected trait implementation. The authored A
trait cases are distinct from the complete original core From declaration,
whose language role and downstream float fallback remain a separate join.
Historical v0-v8 metadata cannot represent reservation polarity and remains
explicitly fenced when that implementation/header semantics must cross crates.
