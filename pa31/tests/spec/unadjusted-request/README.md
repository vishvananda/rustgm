# Unadjusted calling conventions

PA31 owns source feature/macro authority, PA28 owns the ABI and intrinsic
consumers, PA8 owns opaque grammar and PA29 owns convention transport. These
buildout contracts release no whole assignment and establish no upstream crate
artifact.

The active source manifest is `contract-v4.json` / `cases-v4.tsv`: thirty cases
in Rust2021 and Rust2024. Pinned Rust agrees with all sixty outcomes. Requests,
configured removal, unknown features, real foreign declarations, generic functions,
function pointers, convention mismatches, raw/escaped strings and macro origins
retain independent predictions. Enabling the feature creates a distinct typed
Unadjusted convention; it does not substitute Rust or C.

Opaque literal ABI arguments reuse their completed string and parsed literal.
A transparent parser-owned constructor preserves the actual extern introduction
separately from the payload. Its pretty writer emits the ABI string without
expression parentheses. Genuine introduced headers and forwarded ABI literals
use their macro allowance; forwarding a whole caller-authored item grants none.
The underlying literal retains its original bytes and provenance. The feature
validator shares one macro session across actual ABI header columns. It does not
walk bodies or rebuild a growing allowance list for each declaration. Explicit
crate permission takes the constant-time path. Packed ABI/Convention and ordinary
node layouts remain unchanged; opaque ABI construction adds one existing Group
node only where needed.

Primitive scalar execution uses the unchanged backend. The independent C observer
qualifies unsigned byte, u64, u128, f32, f64 and bool interoperation for the exact
signatures in `scalar_native`. The exported source entry additionally runs the
actual reified function-pointer and generic calls. The RustGM source executable
produces the same declared eight observations. Earlier ordinary-C controls with
and without the unused request produce identical LowIR, also identical to the
predecessor's ordinary program. This is no aggregate or SIMD ABI equivalence
claim.

`aggregate-lowering-v1.json` retains the required positive aggregate contract.
Both compilers accept its types. Pinned Rust's actual C wrapper executes17 and
its LLVM signatures demonstrate the difference: raw takes/returns Triple directly,
whereas C uses an sret result and byval input. RustGM currently rejects demanded
aggregate/SIMD lowering explicitly. Its required LowIR success remains recorded;
changing the current boundary into a language rejection would hide unfinished
work. Existing metadata profiles likewise reject an unencoded Unadjusted ABI.
Genuine aggregate/vector calls, LLVM intrinsic operations and authenticated
cross-crate convention transport remain required before general ABI completion.

The original selected-source inventory contains55 textual unadjusted extern
blocks in the375 opened files. An earlier core/src-only search missed stdarch;
the request-only plan was abandoned before compiler implementation. Obsolete
contracts preserve that draft and the independently corrected setup predictions.
The first native foundation tried to implement builtin function-pointer Copy and
Clone and used unary minus without a source Neg role. The successful foundation
uses the actual builtin implementations and positive source f64; the independent
scalar observer still checks negative f64. Reference-v1's captured-literal
prediction was corrected from the pinned oracle before implementation was tested.
An early link omitted the required reporter. Failed private checks exposed the
opaque grammar and constructor-permission gaps; their required positives were
implemented, not changed to failures.
