# Explicit source-contract limits

`contract.json` freezes the exact defaults, three finite CLI inputs and source
controls before observation. The options govern macro contract work, attempted
allocation volume and retained memo payload. Zero is a real limit and no value
means unlimited. Explicit requests never scale themselves from source input.

Ordinary defaults are unchanged. Resource policy grants no feature, macro role,
body, API, unsafe or const permission. The source fixture uses real NoCore
language declarations; the ordinary fixture owns its real local macro allowance.
Both expand the same authored seven-valued body under sufficient limits. Whole
core/alloc/std artifacts remain a separate requirement; an increased-resource
observation must bind all effective limits in its own host manifest.

CLI owner controls use `--emit-names`, which enters the Resolver and constructs
the actual SourceCore or LocalMacros owner. Semantic views enter the same
contract path. Standalone `--emit-expanded` renders without those owner states;
its first test prediction mismatch is retained in the evidence. The successor
contract records this phase boundary before the corrected candidate run.
