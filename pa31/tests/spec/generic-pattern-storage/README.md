# Generic pattern storage (source core)

The tuple, record, ergonomic, nested and parameter controls destructure a generic guard through a
reference, as alloc's local `DeallocDropGuard` does. The selected pattern has
an exact lifetime instance of `Guard` which need not be any expression's type.
Its completed fields are structural data; reading them grants no lifetime or
move permission. The unpaid-lifetime and move-from-reference controls must
remain rejected. Accepted programs print `41 59` through the C observer.

Outcomes and every input hash are declared in `outcomes.json` before execution.
The mini-core foundation is copied from the capture-dereferences packet; its
upstream Rust attribution remains in root NOTICE and third_party/sources.json.

The declared 8/32/128-function family independently checks Rust acceptance and
bounds field-instantiation work as the number of selected patterns grows.

A reference conversion can relate different lifetime instances. CFG dereference
keeps the actual source place's pointee, so its fields must be prepared alongside
the selected pattern's expected types. The nested control passes through a field
projection; the parameter control checks the corresponding function-entry place.

Projection discovery shares the existing source-header query payer. Its
`InputBound::of` already counted every admitted unit's AST nodes and edges before
body checking; the selected pattern roots, match arms, parameters and adjustments
come from those bodies. No second ledger or fixed work cutoff is added. Every
root scan, child edge, queued pair and actual conversion dereference attempt is
charged, including duplicates and failed attempts. A `(PatternId, actual TypeId)`
pair traverses its children once, so graph sharing preserves distinct lifetime
contexts without replaying the same pair's subtree. The 8/32/128 control retains
its declared incremental linear-work bound for field instantiation and canonical
steps; its observations remain pending for this draft.
